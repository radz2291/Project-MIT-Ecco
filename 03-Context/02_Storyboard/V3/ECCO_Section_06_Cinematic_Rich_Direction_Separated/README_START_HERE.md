## Director's one-line idea

**Collected measurements become a 3D borehole → its circumferential surface opens into a 2D map → that cinematic representation gives way to real MIT engineering output.**

## Separation of responsibilities

- **Mechanical board / Ahmed's comments:** technical truth, what the tool actually does, data conventions.
- **This package:** cinematic framing, intended film experience, shot and transition architecture.
- **Next controlled 3D storyboard / animatic:** fixed scene layout, camera/keyframe coordinates, persistent geometry, measured mapping logic, motion timing.
- **Blender execution:** implement agreed geometry, compositing and animation. Do not improvise physical mechanisms.

## Essential cautions

1. S06-A points reconstruct the borehole **from stored data after retrieval**, not live streamed 3D imagery. Section 05 mud-flow lines should fade out; do not morph mud into ultrasound data.
2. S06-B is **not a physical operation performed underground**. The 'longitudinal cut' is a virtual seam in a data representation. Map the same sampled borehole positions using azimuth (horizontal) and measured depth (vertical). Geometry and amplitude are separate data properties.
3. S06-C's **generated display includes artificial data**. It is a composition/mood reference only. The final video must use MIT-approved actual field output (or explicitly identified demo data), never passing generated readings off as real.
4. The supplied real report is **LipanBara / ENP1**, not a verified ENP3 result, and is operator confidential. Get usage approval before public distribution.
5. The images are not approved manufacturing geometry, data visualization algorithms, or composited final shots.

## Suggested review sequence

Review S06-A's exit frame (can the viewer identify an entire borehole?), S06-B's mapping logic (is there one consistent 3D→2D surface?), and S06-C's evidence origin (actual report, permission granted) before locking the animatic.
