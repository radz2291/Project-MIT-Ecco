# Skill Routing and Project Adoption

## One entry point, several specialist tools

This skill owns stage order, context recovery, clear communication and the release decision. AI Director judgment leads the creative work. Specialists contribute their existing methods; they do not launch a competing workflow or produce a second scene contract.

Load only what the current decision needs. Once a specialist returns a useful result, place it in the existing contract and resume the current stage. Do not restart Establish mode recursively.

## Map new gates into the existing contract

| This skill | Existing contract concept | What remains separate |
|---|---|---|
| Gate A — Meaning & Truth | D0 concept readiness | Actual domain approval and publication rights |
| Gate B — Creative Direction | D1 art direction or explicitly released test | Animation/execution approval |
| Gate C — Production Release | D2 execution-ready for the named scope | D3 moving-preview review and D4 finishing |

Do not rename existing statuses or create duplicate gate records. Use one decision record with both labels only if useful. Current project amendments control execution: no mandatory separate editable 3D storyboard, no reinstating an old still/animation pairing, no reopening accepted tickets and no automatic film assembly. A cheap proof is optional and risk-driven, not a new project deliverable by default.

In MIT/ECCO the owner assembles the film and current project render limits still apply. Read their live values; do not bake project-specific timing, dimensions or task IDs into the reusable core.

## Use in Codex

The canonical repository source is `03-Context/00_Skill/rolladice-scene-establishment/SKILL.md`. A repository folder is not automatically proof that the skill is installed or discovered in a local Codex session.

Immediate explicit use after the files are available:

> Read `03-Context/00_Skill/rolladice-scene-establishment/SKILL.md` and use it to establish this scene. Recover existing approvals and begin with the next unresolved decision. Do not start full production until it is released.

For a discovered local installation, use `$rolladice-scene-establishment`. OpenAI's [skill authoring documentation](https://developers.openai.com/codex/skills/) describes repository `.agents/skills`, user-level skill locations, optional `agents/openai.yaml`, explicit invocation and progressive loading. Confirm the actual environment before installing; do not change user configuration or create duplicate same-name copies without permission. This package includes metadata but no automatic installer.

## Portability

The core and its internal references work without MIT assets. On a new project, bind its authority map, scene contract, director/taste sources and production workflow. Optional companion skills may be installed separately or read from an accessible source checkout. Missing companions are disclosed, not falsely claimed as loaded. Critical source facts must still be obtained.

Carry only transferable lessons. Do not copy private logs, product dimensions, brand colors, required fees, personal details or old scene approvals into future projects.
