# Example — Engineering Data Without Endless Texture Revisions

**Origin:** transferable lesson from the supplied ECCO Section 3 collaboration. This is not a field-data validation or a prescribed borehole model.

## The scene in ordinary language

We expected one shape. The actual shape differs. Measurements reveal those differences along the object. A second measured property adds another useful view.

## Resolve the meaning before modelling

Separate four beats: expectation, unexpected condition, measured interpretation through extent, and another information layer. Establish what the viewer already learned in the previous scene. Do not build the same reconstruction again unless the repetition earns new understanding.

## Resolve truth before making a condition more dramatic

Use a fixed, correctly registered nominal reference. A color classification must follow the actual relevant value, not camera projection or painted masks. Check whether the desired example exists in the source.

If a tiny difference is hard to see, first use a better comparison or magnified view. A different illustrative variant is allowed only with explicit scope and disclosure. It remains separate from source evidence. A geometric clearance in one centered cross-section is not proof that a moving assembly can pass in real operating conditions.

For this lesson there is no need to reuse ECCO's provisional radii. Future projects must inspect their own geometry and operating limits.

## Separate the data, surface, shader, view and animation

When a mapped image looks like folds or material, test the same image on a flat plane, a simple surface and the actual geometry. Hold display settings constant. Then change the viewpoint alone. Check UV landmarks, orientation and seams where relevant.

If the fold impression exists on the flat source and ideal cylinder, do not keep blaming the irregular mesh. If an unlit material has been verified, stop requesting removal of nonexistent metal shading. The test result must change the next hypothesis.

Compare the source design against a real, authorized visual reference. Natural-looking texture is not automatically scientifically wrong, and a pixelated image is not automatically data. Appearance approval means it communicates the chosen idea; it does not certify actual sensor values.

## Fixed values, changing visibility

Define the complete map first. Reveal it through a separate mask. A multi-region organic reveal can expose fixed recorded information without implying physical information spreading between locations. Keep amplitude, geometric shape, display color and mask progress distinct.

A synthetic texture may need an authorized seamless derivative for a cylindrical display. Preserve the original and document the repair. Do not silently alter genuine measured pixels to improve tiling. Visible screen-cell size is a style decision, not a claim about acquisition resolution.

## Choose scene independence deliberately

An immersive acquisition scene and a clean scientific comparison can be separate files joined by motion. Shared visual language does not require a common camera. Shared evidence identity does require consistent data or a clearly explained shift to another example.

## Release after the right proofs

Approve geometry, image design, mapping, effect timing and integration separately, but reuse approvals instead of inventing more gates. A matched still may settle the texture choice. A short reveal settles motion. The complete shot checks the four discoveries with the intended narration and labels. Once it passes, stop revising the texture because of an unrequested taste change.
