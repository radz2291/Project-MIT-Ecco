## Linking and propagation contract

Use immutable, versioned masters with a published top-level collection and a sidecar manifest: source hashes, units, coordinate basis, control schema, dependencies, rights, limitations and consuming shot IDs. New wrappers should link hardware and data rather than copy their geometry. Package legacy components under Shared/Assets in future build tasks; retain the original mechanism proofs.

Shot sources live at `04-Production/Shots/<section>/<V3-shot-id>/Scenes/`. Blender library paths must be relative and resolve from the saved consumer; record the resolved project-relative path and SHA as well. A nested Scenes folder requires its own correctly calculated relative path, not one copied from a differently nested proof. Test a fresh reopen after relocation.

Allow shot-local camera, timing, lighting, visibility and approved material/graphic overrides through explicit controls or documented library overrides. Geometry, sensor references, dimensions, quantity values and provenance stay master-owned. Do not append a whole legacy proof into each shot and call the result shared. An unavoidable append needs source hash, local-difference record and explicit rebuild/relink ownership.

For each revision: identify changed component IDs → expand consumers from shot-map JSON → update a new version of the shared manifest → relink only released shots → check dimensions, controls, contact/return, clearance, masks, seam/color correspondence and both adjoining cuts → benchmark again → rerender affected shots → return changed meaning/appearance for Radzi review. Radzi updates his edit from exact replacement shot versions. Preserve old renders/sources and record which consumers have and have not migrated.
